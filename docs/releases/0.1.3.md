# Modbus Monitor 0.1.3

Persistent Android login and ADMIN configuration editing through Cloud to the owning Edge.

## Changes

- Mobile sessions no longer expire by time. Explicit logout, account disable and password
  changes/resets still revoke access. Browser sessions keep their existing expiry and CSRF rules.
- A still-valid previous APK session can be promoted without storing a password. Expired
  sessions require one new login; Android stores session cookies using the platform Keystore.
- Cloud ADMIN can edit Locations, Connections, Devices, Tags, Automation, Alarm rules,
  Dashboards, widgets and layout from the updated APK. Normal Cloud web configuration stays
  read-only. Changes are validated and applied by the owning Edge through a durable request.
- Reject stale configuration versions and cross-Edge references. Expired requests are not
  applied; duplicate delivery returns the recorded result without executing CRUD again.
- Mirror updated metadata before returning a completed edit. Pending/uncertain edits remain
  visible in the APK request status panel; the client never blindly retries a mutation.
- Preserve existing manual Commands, read-back verification, authorization and write settings.
  Serial discovery and transport testing remain local worker operations.

## Upgrade order

Minimum installed backend: **0.1.2**. New migration:
**`0016_mobile_remote_configuration`**, following `0015_configuration_archive`.
Previously applied migrations are unchanged.

1. Take encrypted backups of Cloud and Edge; keep passphrases outside the databases.
2. Upgrade **Cloud first** through System -> Updates with the existing host runner. Verify
   application **0.1.3**, migration **0016_mobile_remote_configuration**, database health,
   login and the Edge heartbeat. Publishing this release does not deploy it automatically.
3. Upgrade **Edge second** using its existing maintenance procedure. Stop the configured
   API/worker/sync before migration, upgrade the installed server package and run Alembic
   `upgrade head`; restart exactly one worker and sync client. Native Edge installation
   through Updater v1 remains unsupported. Preserve the existing `.env`, installation ID,
   tokens and `MODBUS_WRITES_ENABLED`; do not replace them with example environments.
4. `REMOTE_CONFIGURATION_ENABLED=true` (the default) enables this Edge's
   `configuration-v1` capability. Set false to refuse remote edits. Cloud delivery expiry
   defaults to `REMOTE_CONFIGURATION_MAX_AGE_SECONDS=300`. Wait for the new heartbeat
   and metadata before editing through Cloud. Keep outbox records during interruptions.
5. Install Android **0.1.2 / versionCode 3** from the separate private Android repository.
   Test with a disabled rule or harmless Dashboard label/layout change, not a physical write.

Updating Cloud alone does not make an older Edge accept configuration edits. The release
does not enable physical writes, execute commands, replace the shared gateway, modify
production topology or update an APK. The previous compact Android layouts remain intact.

## Migration and recovery

The migration makes mobile session expiry nullable and adds Edge capabilities and
configuration request/result support to the existing remote queue. Existing command and
acknowledgement records remain valid. Application-only rollback after schema migration
is not assumed safe; use the documented controlled backup recovery procedure. Downgrade
refuses retained configuration request history rather than erasing it. Never remove volumes.

## Release assets

Attach **both** `modbus-monitor-0.1.3.tar.gz` and `modbus-monitor-0.1.3.json`. The detached
manifest contains archive/per-file SHA-256 hashes, minimum version and migration head.
The archive contains tracked server/frontend build inputs only, not environments,
databases, backups, APKs or gateway configuration. GitHub-generated source archives
are not usable updater artifacts.
