# Modbus Monitor 0.1.2

Safe configuration deletion with retained history, plus Automation fixes since 0.1.1.

## Changes

- Delete Tags, Devices, Connections, Locations, Automation rules and Alarm rules even when
  historical records exist. Objects are retired from active configuration; telemetry history,
  command results, alarm events and automation executions remain attached to their original IDs.
- Retire dependent rules explicitly, cancel pending commands and remove obsolete dashboard
  bindings. An in-flight write/read-back is protected; uncertain writes are never replayed.
- Reuse a retired Tag key or Device slave address for a new identity without mixing histories.
- Synchronize retirement to Cloud without allowing delayed current values to revive deleted Tags.
- Fix Cloud Automation reads for incomplete mirrored rules instead of returning HTTP 500.
- Include the previously committed stateful Automation output reconciliation and rule-edit fixes.
- Keep native Edge autostart configuration local to its installation.

Deletion does **not** turn physical outputs OFF. Put equipment into its intended safe state
through the existing verified command flow before deleting its configuration. There is no
unarchive or permanent history-purge UI in this release.

## Upgrade order and compatibility

Minimum installed application version: **0.1.1**. New database migration:
**`0015_configuration_archive`**, following `0014_backups`. Previously applied migrations
are unchanged.

1. Take encrypted full backups of Cloud and Edge; save the passphrases outside the databases.
2. Upgrade **Cloud first**, using **System -> Updates** with the existing configured host runner.
   Confirm application version `0.1.2`, migration `0015_configuration_archive` and database health.
3. Upgrade **Edge second**, during a local maintenance window using its existing manual workflow.
   Stop the actual configured worker/sync and API services before applying migrations; restart
   exactly one worker and sync process afterwards. Native Edge installation through Updater v1
   is not supported.
4. Verify telemetry, heartbeat and synchronization catch-up before using configuration deletion.

Old Cloud cannot ingest the new archival metadata. If Edge was upgraded first, leave its
outbox intact and upgrade Cloud; do not erase pending records to resolve a version mismatch.
Environment files, Edge credentials, physical-write settings, database volumes and the
independent Caddy gateway are preserved. No physical commands are part of update validation.

The updater takes and pins an encrypted backup before installation. After an attempted schema
migration it does not blindly downgrade or claim binary rollback is safe. Follow controlled
backup recovery if migration/startup fails. Downgrade of `0015` refuses reused keys/slave IDs
that would violate the old uniqueness constraints.

## Release assets

Use both `modbus-monitor-0.1.2.tar.gz` and `modbus-monitor-0.1.2.json`. The detached manifest
contains the SHA-256, per-file hashes, canonical version, minimum version and migration head.
GitHub's automatically generated source archives are not Updater artifacts. Application assets
contain only reviewed server/frontend build inputs, excluding credentials, local environment
files, databases and backups.

See [configuration deletion](../deletion.md), [manual updates](../update.md) and
[backup recovery](../backup-restore.md) for operational details.
